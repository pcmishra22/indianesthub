WHAT THIS PATCH FIXES
======================
You asked: when a stock like Titan is picked twice for Buy (hitting target
both times) and then picked for Sell, the report should clearly show all 3
rows — 2 achieved, 1 open at its own target — with no confusion, and the
current price should always be tracked live.

I checked the whole recommendation engine (Prakash momentum engine + AI
engine) and the multi-occurrence logic itself was ALREADY correct — a
symbol correctly gets a brand-new row (with its own entry price/target)
every time a fresh signal fires after the previous one is closed out
(occurrence 1, 2, 3...). I verified this with a direct test (Titan bought
twice + sold, all 3 rows tracked and resolved independently and correctly).

The real gap was in the REPORT screen (EOD tab → "Momentum+AI Report"):

1. It only showed Entry price + Target price + Status — no "current price"
   column at all, so you couldn't tell how close a stock was to target.
2. The current/live price and achieved-status shown there were only ever
   as fresh as the last time the Watchlist tab happened to auto-refresh.
   If you opened the EOD report without the Watchlist tab having ticked
   recently, it could show a target as "Open" even if it had actually
   already been hit.
3. Multiple rows for the same stock (occurrence 1, 2, 3) could appear
   scattered rather than grouped in order, which is exactly the
   confusion you described.

WHAT CHANGED
============
1. app/prakash_recommendations.php
   - Added prakashRefreshRowsLive() + prakashBuildQuoteLookup(): fetches a
     fresh live quote for every symbol in a day's report and re-checks each
     still-open row against its own target right then, flipping it to
     achieved immediately if hit. Stamps a clear status_label:
     OPEN / ACHIEVED / NOT ACHIEVED (no more guessing from booleans).

2. app/api/routes.php
   - /api/eod/combined now: closes out the day first if market close has
     passed (so it never has to show as "Open" a signal that should read
     "Not Achieved"), fetches live prices for every tracked symbol, updates
     achieved/status_label/current_price accordingly, saves it back so the
     rest of the app stays in sync, and sorts rows by stock+time so repeat
     picks for the same stock (Buy, Buy, Sell...) sit together in order.

3. app/views/dashboard.php
   - The "Momentum+AI Report" is now a real table with the exact columns
     you asked for: Stock | Signal | Given By | Recommended | Current |
     Target | Status — plus an occurrence badge ("2nd pick", "3rd pick")
     on repeat stocks, and a color-coded gap% next to the current price.
   - The CSV download and the "Top Recommendation for Today" boxes on the
     Watchlist tab got the same current-price + clear-status treatment.

HOW TO DEPLOY
==============
This patch only touches these 3 files — nothing else in your app needs to
change, and none of your storage/*.json data will be touched by this zip.

1. Upload/overwrite these 3 files on your server, keeping the same paths:
   app/prakash_recommendations.php
   app/api/routes.php
   app/views/dashboard.php

2. No artisan/migration/composer step needed — this is a plain PHP file
   app, so it's live as soon as the files are uploaded.

3. Open the dashboard → EOD Report tab → check "Momentum+AI Report" shows
   the new table with a Current price column. If the market is open, give
   it a few seconds — it fetches live prices when the tab is opened.
