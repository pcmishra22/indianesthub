STOCK ANALYZER — PATCH: env-driven Prakash settings + bad-tick guard
=====================================================================

WHAT CHANGED
------------
1. app/config.php
   - .env loading moved to the TOP of the file (was loading too late
     before, so getenv() calls used further down never actually saw
     your .env values).
   - PRAKASH_TARGET_PCT, AI_TARGET_PCT, PRAKASH_FAST_MOVER_THRESHOLD_PCT,
     PRAKASH_MAX_PER_BOX, AI_MAX_PER_BOX are now all read from .env
     (with the same defaults as before if not set).
   - NEW: PRAKASH_MAX_TRACKED (default 20) — this replaces the old
     hardcoded "20" cap on how many stocks Prakash ranks/tracks.
     Set PRAKASH_MAX_TRACKED=40 (or any number) in .env to track more.
   - NEW: PRAKASH_MAX_PLAUSIBLE_MOVE_PCT (default 12) — sanity guard,
     see below.

2. app/prakash_recommendations.php
   - Hardcoded "20" replaced with the new PRAKASH_MAX_TRACKED constant.
   - NEW function prakashIsPricePlausible(): before locking in an entry
     price or marking a target "Hit", the live price is checked against
     that stock's own previous close (derived from change_pct). If the
     implied move is bigger than PRAKASH_MAX_PLAUSIBLE_MOVE_PCT, that
     tick is treated as a bad/glitched read and skipped — it can no
     longer lock in a wrong entry price or falsely mark a target as hit.
   - Daily records now also store entry_source / achieved_source
     (which data provider — bse/stooq/nse/groww — supplied that price),
     so if something looks off again you can check exactly which source
     it came from instead of guessing.

3. app/ai_recommendations.php
   - Same bad-tick guard and entry_source/achieved_source tracking
     applied to the AI recommendation engine (it had the identical
     locking logic as Prakash).

4. app/api/watchlist.php
   - Each stock's quote source (_source: bse/stooq/nse/groww) is now
     carried through into the $stocks array so the above can use it.

5. .env.example
   - Documents all the new/now-configurable variables.

ABOUT THE INFY PRICE ISSUE YOU FLAGGED
---------------------------------------
The entry/target price was never coming from a "cache" file — it's the
live price at the moment a stock FIRST enters a Buy/Sell box that day,
locked in from whichever data source answered first (BSE, then Stooq,
then NSE, then Groww, in that priority order). Once locked, entry price
and target never change for the rest of the day — only the "Hit" status
updates.

Given INFY's entry (Rs 1,057.85) and its "Hit" showing at a target
(Rs 1,068.43) that's above today's actual high (~Rs 1,053), the most
likely explanation is a single bad/glitched read from one of the
fallback providers on one refresh — either at the moment of first
capture (wrong entry) or a later refresh (false "Hit"). Because both
values used to be locked in immediately and permanently, one bad tick
could freeze a wrong number for the whole day with no way to recover
except waiting for tomorrow's fresh file.

The new prakashIsPricePlausible() guard now catches this case: it
rejects any single-refresh price that implies more than a ~12% move
from that stock's previous close (adjust via PRAKASH_MAX_PLAUSIBLE_MOVE_PCT
in .env) rather than trusting it. It also now stores the source that
supplied each locked price so future anomalies can be traced instantly
instead of guessed at.

Note: I don't have access to your live server logs/today's actual
tracking file, so I could not directly confirm which specific provider
glitched for INFY today. If you want to confirm root cause instead of
just guarding against it going forward, you can grab and send me:
  storage/_prakash_daily_2026-07-06.json     (or under users_data/ for
  a specific user, e.g. users_data/<username>_prakash_daily_2026-07-06.json)
That file will now include "entry_source" / "achieved_source" going
forward, showing exactly which provider (bse/stooq/nse/groww) supplied
the price that got locked in.

HOW TO DEPLOY
-------------
1. Upload these 4 PHP files, overwriting the existing ones at the same
   paths in your project:
     app/config.php
     app/prakash_recommendations.php
     app/ai_recommendations.php
     app/api/watchlist.php

2. Open your LIVE .env file (not .env.example) and add these lines
   (adjust values as you like):

     PRAKASH_TARGET_PCT=1.0
     PRAKASH_MAX_TRACKED=20
     PRAKASH_FAST_MOVER_THRESHOLD_PCT=1.0
     PRAKASH_MAX_PER_BOX=5
     PRAKASH_MAX_PLAUSIBLE_MOVE_PCT=12.0
     AI_TARGET_PCT=1.0
     AI_MAX_PER_BOX=5

   (.env.example is included here for reference only — don't overwrite
   your real .env, just add these keys to it.)

3. No artisan/migration commands needed — plain PHP, no framework.
   No database schema changes either.

4. Test: open the dashboard, confirm Prakash/AI boxes still load and
   the "Today Buy/Sell" counts look sane. If you set
   PRAKASH_MAX_TRACKED=40, you should be able to get more than 20
   tracked recommendations from tomorrow's fresh daily file onward
   (today's already-locked entries won't change retroactively).

All 4 PHP files pass `php -l` syntax checks.
